## 仿生设计库文献提参流水线设计文档

### 概述

本文档定义了从文献库中提取参数以填充仿生设计库的完整流水线方案。方案采用"由轻到重、迭代精化"的策略，分四个阶段推进：粗扫建立原型画像、差距分析识别知识缺口、定向补充文献、深潜提参填充知识库。

### 背景与问题

仿生设计库的框架已完整（分类体系、feature-mapping.json、原型模板均已就绪），但33个原型目录全部为空，需要从文献中提取参数来填充。

现有的341篇文献库存在三个核心问题。第一，文献视角偏"材料→应用"——大量论文是关于"某材料对某污染物的吸附性能"，而非"从某生物原型提取某特征来设计某材料"，导致仿生叙事、设计映射等深层字段无法从现有文献中提取。第二，缺少方法论层面的文献——没有仿生学方法论标准（ISO 18404、VDI 2083等）来指导提参的标准化流程，也缺少跨原型的系统性比较研究来支撑权重赋值。第三，检索方向偏差——筛选标准偏向材料科学领域常用的"优先综述、高引用、近5年"，导致进来的多是材料性能综述而非仿生设计逻辑综述。

### 整体策略

采用并行推进策略：从现有文献中提取性能数据，同时补充仿生设计类文献来填充仿生叙事和权重。两条线并行但不独立——通过差距分析环节将两者有机衔接。33个原型全覆盖，不做优先级区分。

文献补充覆盖四种类型：仿生学方法论与标准、仿生设计综述、跨原型比较研究、仿生设计案例研究。

### Phase 1：粗扫

#### 目标

用最低成本从现有341篇文献中为33个原型各建立一份粗略画像，为差距分析提供数据基础。

#### 文献到原型的映射

现有文献按机制分组（第1组配位螯合、第2组超疏水等），但原型是按生物体分的（贻贝足粘附、荷叶、硅藻等）。需要建立映射层。

映射采用两步走策略。第一步用文件名关键词自动匹配——文件名含"mussel/贻贝"的归入 mussel-foot-adhesion，含"lotus/莲"的归入 lotus-leaf，含"diatom/硅藻"的归入 diatom-microspheres，以此类推。第二步对无法通过文件名匹配到的论文（预计一半以上，因为大量论文是关于通用材料如壳聚糖、MOF的），按所属机制组归入该机制下的所有相关原型，标记为"间接关联"。

#### 提取字段

粗扫阶段只提取能在文件名和摘要层面获取的字段：目标污染物（从关键词和摘要）、主要吸附机制（从分组+关键词）、材料类型（从关键词）、性能范围估计（qmax和去除率，如果摘要中有的话）、适用pH和温度范围（如果摘要中有的话）。仿生叙事、设计映射、工程约束等深层字段在此阶段留空。

#### PDF处理方式

341篇全做全文提取成本过高。粗扫阶段采用"文件名解析 + 摘要提取"方式：文件名解析用规则引擎直接提取年份、作者、关键词；摘要部分用 PyMuPDF 提取PDF首页文本，再用LLM从首页文本中定位和提取摘要。

#### 模型选择

粗扫任务是比较标准的文本理解和信息抽取，使用 qwen3.7-plus 或 qwen3.6-flash 即可，不需要 qwen3.7-max。

#### 产出

每个原型生成一份 `coarse-profile.json`，包含已提取字段的值、置信度标记（高/中/低）和来源论文ID列表。同时生成一张覆盖度热力图，展示每个原型的文献覆盖数量和主题匹配度。

### Phase 2：差距分析

#### 目标

识别每个原型的知识缺口，为定向文献补充和深潜提参提供精确指引。

#### 两步结构

差距分析采用"粗扫判广度 + 精读样本判深度"的两步结构。

第一步：粗扫判广度和相关性。基于341篇的粗扫结果，回答两个问题——每个原型有多少篇论文覆盖（广度）？这些论文的主题跟原型的匹配度如何（相关性）？产出覆盖度热力图。

第二步：精读样本判深度和结构完整性。为每个原型挑选2-3篇最相关的论文做全文精读（用 qwen3.7-max 提取），用 prototype-template 的全部字段去试着填一遍。这样实证检验现有文献到底能不能支撑仿生叙事、设计映射、工程约束这些深层字段，以及深度是否足够。

#### 差距分类

缺口分三种类型。数据缺口指字段有值但置信度低或数据点太少（比如某个原型只有1篇论文支撑，或者 qmax 只从摘要中粗略估计了一个范围），可以通过对现有文献做全文深潜来弥补。知识缺口指字段完全为空且现有文献中不可能提取到（仿生设计叙事、关键特征提取、设计映射、工程约束），只能通过补充仿生设计类文献来弥补。权重缺口指某个原型在 feature-mapping.json 中的权重缺乏足够证据支撑（只有一个数据点、没有跨文献交叉验证），需要比较性文献或更多数据点。

#### 差距到文献类型的映射

数据缺口指向"对现有文献做全文提取"，不需要下载新论文。知识缺口指向"需要补充仿生设计综述或案例研究"，并标注具体主题（比如"贻贝足粘附的仿生设计叙事"）。权重缺口指向"需要补充跨原型比较研究"。方法论层面的缺口统一补充仿生学方法论与标准类文献。

#### 产出

每个原型生成一份 `gap-report.json`，列出每个字段的状态（已填充/低置信度/空缺）、缺口类型、建议的补充方式（全文提取/补充文献/比较研究）以及具体需要的文献主题关键词。同时生成全局的 `supplementation-plan.md`，汇总所有原型的文献补充需求，去重合并后形成最终的文献补充清单。

### Phase 3：定向文献补充

#### 补充策略

基于差距分析的 `supplementation-plan.md`，按差距类型分流补充。

知识缺口按原型维度搜索仿生设计综述和案例研究。搜索词采用仿生设计导向，格式为"biomimetic design + 生物原型名 + 特征/机制"，而非原来的"某材料+某污染物+吸附"这种材料应用导向。

权重缺口搜索覆盖多个原型的系统性综述或元分析，比如"biomimetic adsorption strategies comparative review""nature-inspired water treatment comprehensive review"。

方法论缺口补充仿生学方法论与标准类文献——ISO 18404（仿生学术语和概念框架）、VDI 2083（仿生设计指南）、Biomimicry 3.8框架等。

#### 搜索渠道

英文文献走 Web of Science 和 Google Scholar，中文文献走知网（CNKI）。

#### 筛选标准

筛选标准从原来的"优先综述、高引用、近5年"调整为：优先包含完整仿生设计逻辑链的论文（从生物观察到材料设计的全流程）、优先明确讨论了"特征提取"或"设计映射"的论文、优先跨原型/跨机制的比较性研究。综述类优先但不是硬性要求，高质量的案例研究同样有价值。

#### 文献管理

在现有文献库 `/Users/panyao/Desktop/仿生文献库/论文/` 下新增四个目录：第9组-仿生方法论（方法论与标准类）、第10组-仿生设计综述（仿生设计综述类）、第11组-跨原型比较（比较研究类）、第12组-仿生设计案例（案例研究类）。文件名沿用现有命名规范（年份-作者-关键词），并在文件名或元数据中标记其关联的原型ID。

### Phase 4：深潜提参

#### 三种任务类型

深潜提参分为三种任务类型，各自有不同的 prompt 设计和模型选择。

**任务一：性能数据提取。** 从现有文献全文中提取结构化数据——qmax、去除率、pH适用范围、温度范围、盐度耐受、动力学参数等。这类任务比较机械，使用 qwen3.7-plus。prompt 结构为：给定论文全文文本和 prototype-template 的性能字段列表，要求LLM输出结构化JSON，每个字段附带值、单位、来源段落引用。论文中没有相关数据的字段输出 null，不编造。

**任务二：仿生设计知识提取。** 从补充的仿生设计文献中提取深层知识——生物原型解决的自然问题、进化策略、关键功能基团/结构特征、从生物到材料的设计映射、必须保留的特征与可调整的特征、工程约束（抗菌性、耐酸碱性等）、一句话仿生故事。这类任务需要理解复杂的因果关系和设计逻辑，使用 qwen3.7-max。prompt 结构为：给定论文全文和 prototype-template 的仿生叙事字段定义（参照 feature/biomimetic-story-v2 分支的模板），要求LLM以结构化方式输出，并标注每个论断的证据来源。

**任务三：权重赋值。** 综合性能数据和设计知识，为 feature-mapping.json 中的每个 pollutant-prototype 和 feature-prototype 映射条目赋权重（0-1）。按照 feature 分支定义的原则：70%基于推理知识（生物原型的机制与目标污染物/特征的逻辑匹配度）、20%基于文献数据（有多少篇论文证实了这个映射）、10%基于证据链强度（数据一致性、跨文献交叉验证）。使用 qwen3.7-max。prompt 结构为：给定一个原型的完整 coarse-profile 和所有相关论文的提取结果，要求LLM对该原型在 feature-mapping.json 中的每个映射条目输出权重值和打分理由。

#### 质量控制

每个原型的提参结果经过两轮校验。第一轮自动化校验：检查所有必填字段是否有值、数值字段是否在合理范围内（qmax 不能为负数）、pH范围是否在0-14之间、权重是否在0-1之间。第二轮人工审核：提参结果以易读格式呈现给团队成员审核，确认无误后才正式写入。

#### 写入流程

校验通过后，脚本自动将提参结果按 prototype-template 的格式写入对应原型目录下的 prototype.md 文件（YAML frontmatter + Markdown 正文），同时更新 feature-mapping.json 中对应原型的权重值。所有写入操作都有 git 跟踪，可以随时回滚。

### 模型分级策略

整个流水线采用模型分级策略以平衡质量和成本。粗扫阶段（文件名解析+摘要提取）使用 qwen3.7-plus 或 qwen3.6-flash。精读样本和深潜提参中的仿生设计知识提取、权重赋值使用 qwen3.7-max。性能数据提取使用 qwen3.7-plus。

### 工具链

批处理脚本使用 Python，PDF文本提取使用 PyMuPDF（fitz），文件遍历和元数据解析使用标准库。LLM 调用通过 API 接口实现。提参结果以 JSON 格式中间存储，最终写入 prototype.md（Markdown + YAML frontmatter）和 feature-mapping.json。
